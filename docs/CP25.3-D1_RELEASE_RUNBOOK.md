Preflight verifica Java, certificado parseable, consola y classpath; NO abre conexión.
No certifica la cadena del servidor ni permisos remotos. Esos controles los valida JDBC
verify-full y el CLI al ejecutar la operación futura autorizada.

Solo después de aprobación explícita del alta, ejecutar el mismo comando SIN
-PreflightOnly. No se incluye ahora un host/usuario asumido como comando listo.
Si no hay DB_PASSWORD inyectado por un gestor al entorno del proceso, el script pide
la contraseña DB con Read-Host -AsSecureString. No pasar secretos por argumentos,
Set-Content, .env, perfil, transcripción, variable persistente de usuario ni chat.
El CLI pide los datos nominales y DOS veces la contraseña del administrador sin eco.
Mínimo 16 caracteres y máximo 72 bytes UTF-8. No se solicita en el script ni se escribe
en archivos. DB_PASSWORD se transmite solo por entorno de proceso al JVM, se restaura
el entorno previo y se limpia el BSTR/SecureString al terminar. Los strings temporales
del runtime no ofrecen garantía de borrado físico de memoria; usar equipo confiable,
sin dumps ni instrumentación/transcripción y cerrar la terminal después.
No usar opciones JVM heredadas, agentes, hosts overrides ni proxies QA en una ejecución DEV.

El CLI existente valida URL/base/usuario/PG16/TLS, usa BCrypt, advisory lock transaccional,
rechaza cualquier administrador existente y username/email duplicados, crea un único
SIMERTPI_ADMIN habilitado y audita atómicamente. No promueve ni resetea cuentas.
Flyway excluido, ddl-auto=none, SQL init=never, sin HTTP. Una segunda ejecución puede
agregar auditoría de rechazo; no cambia la contraseña ni otras cuentas.
